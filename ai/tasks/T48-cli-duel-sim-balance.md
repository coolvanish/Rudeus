## Goal
The duel is a game by measurement, not by hope. Today it is not: T55 measured that plain dashes almost never push
anyone off (two NORMAL FLY or HIDE bots end 92–99 % of rounds by the clock at about 700 hits per ring-out; EASY
against EASY is 100 % clock), and nearly every ring-out comes from the JUMP stomp or the ROLL ram. This brief gives the
CLI a `duel` command that plays and tabulates thousands of matches, tunes the numbers until the acceptance table
below holds, and commits the new defaults with the table that proves them.

## The `duel` command
```
duel match  --a <fighter> --b <fighter> [--arena empty|cup|small|large] [--level-a easy|normal|hard] [--level-b ...]
            [--seed N] [--step-ms 33] [--params file.json]
duel series ... --n 200
duel matrix [--level normal] [--arenas all] [--n 200] [--seed 1] [--params file.json] [--bundle docs/bundled] [--out dir]
duel tune   [--budget N] [--out build/duel/tuned.json]
```
- `<fighter>` is an ability with optional stats, `fly` or `roll:7,6,5,2` (power,speed,guard,agility), or `@<ref>`:
  a bundled character, read from `<bundle>/<ref>/sheet.json` (`sheet.fighter`, `sheet.ability`).
- `matrix` prints and writes (`matrix.md`, `matrix.json` under `--out`, default `build/duel`; never `runs/`):
  the 4 x 4 ability table with archetype stats (win share, clock share, mean match seconds, hits per ring-out per
  cell and against the field); the stat table (for each ability: a specialist with one stat at 8 and the others at 4
  against the balanced 5/5/5/5, one row per stat); the bundled round-robin when `--bundle` is given; and the
  acceptance verdicts below, PASS or FAIL with the number.
- `--params file.json` is a `DuelParams` JSON (the serializer in `:core`), so a candidate can be measured without
  recompiling.
- Deterministic: the same arguments print the same table. Fast enough: say how long `matrix` takes at `--n 200`.
- The key is never needed and never read: nothing here calls a model.

## Acceptance table (measured by `duel matrix`, fixed seeds, n >= 200 per cell; NORMAL vs NORMAL and HARD vs HARD)
| # | Criterion | Threshold |
|---|---|---|
| A1 | No ability dominates: win share of each ability against the field (the other three, archetype stats), per arena | 35 %..65 % |
| A2 | No single matchup is hopeless | every cell 25 %..75 % |
| A3 | Rounds are decided on the table, not by the clock: share of rounds ended by the clock, per ability pair | <= 25 % on EMPTY, CUP_AND_BOOK, SMALL; <= 40 % on LARGE |
| A4 | A ring-out takes a few good hits: mean hits per ring-out, from the marks | 2..8 |
| A5 | A match is a short game: mean match length in match time | 30 s..120 s |
| A6 | Every specialist is viable and none is the answer: one stat at 8, the rest at 4, against 5/5/5/5, same ability | 40 %..65 % |
| A7 | Stats do something: an illegal 8/8/8/8 against 5/5/5/5, same ability | >= 65 % |
| A8 | The same table at 16 ms and 33 ms steps | identical (the runner's guarantee) |
| A9 | All existing `core/duel` tests green with the new defaults; a test that pinned an old default is updated and listed | — |

## What may change, in this order
1. **Numbers** in `DuelParams` (knockback speed and decay, dash speed / length / cooldown, the stat factors, stun,
   wall slam, every special's numbers), `DuelRules` (round length) and the bots' numbers in `BotTuning`.
2. **Wobble**, if numbers alone cannot satisfy A3 and A4 on SMALL and LARGE at once (a hit strong enough to matter on
   a 120 cm table is a one-hit ring-out on a 30 cm one). The standard answer of ring-out games: every hit a fighter
   takes in a round makes the next one push it farther. `DuelFighter.wobble: Float` (0 at the start of each round),
   `+wobblePerHit` per hit taken (clashes count), knockback multiplied by `1 + wobbleKnockScale * wobble`, capped at
   `wobbleMax`; optional slow decay `wobbleDecayPerS`. All in `DuelParams`, validated; `wobblePerHit = 0` is exactly
   today's physics and every T42/T45 test must pass with it at 0. Not hit points: nobody loses by wobble alone, it
   only makes the edge closer. If you add it: `DuelMatch` clears it when a round starts, the fuzz keeps its
   invariants with it on, `SideModel` gains `wobble: Float` (0..1 of `wobbleMax`) in `DuelHudModel.kt` with one test,
   and the Result says so first, because it is a rule change the user must see.
3. Anything else that changes a rule (hits and height, the marks' distance, what the clock awards) is NOT yours:
   measure it, describe it under "What a human must decide" in the Result, and leave the code alone.

Method: build the command and the matrix first and commit the baseline table (today's defaults) as the first version
of `docs/duel-balance.md`: that is the "before". Then tune. Keep a short log of each candidate in the Result (what
changed, which criteria moved). Time-box: if after about fifteen candidates some criterion still fails, stop, commit
the best candidate that breaks nothing (A8, A9 always hold), and report exactly which criteria fail and by how much.
The optional `duel tune` is a convenience (coordinate descent or random search over a declared subset of parameters
against the same criteria); do not let it eat the budget.

- **What a human must decide** (measured, code left alone; none of it is T48's to change):
  1. **Wobble itself** (above): keep it as the rule that makes a big table playable, or say no and accept rounds that end
     by the clock on large tables. `wobblePerHit = 0` turns it off (every T42 / T45 test passed with it at 0, commit
     404017c); the HUD needs a way to show it (T50: `SideModel.wobble`).
  2. **A child who walks back to the middle after every hit** needs 11 hits on the 120 x 60 cm table (the bots, who do
     not, need 6.6..6.8). A stronger wobble (0.9 per hit) or a fade-free larger cap would bring it down at the cost of the
     small table (already 3.5 hits).
  3. **The specials that are hits** (JUMP stomp, ROLL ram) do not wait for the dash cooldown, so with wobble each is an
     extra step to the edge; numbers alone had to make the stomp softer than a dash (0.85 x) and shorten the ram
     (1.3 x long, 1.1 x knock), and ROLL still wins 80.5 / 19.5 at equal stats on the 60 x 40 table. A rule (a ram or
     stomp spends the dash cooldown too, or adds no wobble) would let them stay strong.
  4. **FLY's archetype 3/7/3/7** (`FighterStats.defaultFor`, domain): 23.5 % against 5/5/5/5 on the empty table with the
     same ability. SPEED is worth little to a bot (both reach dash range at once); POWER and GUARD decide. A human picks:
     a FLY line closer to 5/5/5/5 (4/6/4/6?), or SPEED doing more than walking (a longer or faster dash), or neither.
  5. **The small table is short** (23.7 / 25.8 s against 30 s) because 3.5 hits from 7 cm do it. The match rules
